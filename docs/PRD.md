## 1. 产品愿景与问题陈述

### 1.1 愿景

为拥有 **大量外置盘 / NAS / 本机目录** 中视频与照片的用户，提供 **零额外后端依赖**（除 ffmpeg 与可选 Ollama）的 **流式浏览、轻量审阅、可选 AI 辅助归档** 工具；可在桌面终端、macOS `.app`、Windows 可执行包或 **Docker** 中运行。

### 1.2 要解决的问题

| 痛点 | 产品应对 |
|------|-----------|
| 文件夹层级深、媒体分散 | 以「**作品**」（一级子目录）聚合展示，支持根目录平铺兜底 |
| 外置盘/NAS 随机读昂贵 | 可配置 **扫描并发、条带缩略图数量、磁盘 profile**；单次 **ffprobe** |
| 浏览器难播部分封装 | **`/play`** 实时转码为更易播格式 |
| 人工筛选「保留/待审」 | **localStorage** 持久化标签；画廊与列表联动 |
| 批量按语义重命名 | **Ollama 视觉模型**抽帧分析 → 预览映射 → 执行/回滚（同目录内） |

## 2. 目标与非目标

### 2.1 目标（Goals）

1. **G1 可发现性**：用户能在合理时间内看到「作品」列表及扫描进度。  
2. **G2 可播放性**：常见格式直接播放；难播格式可转码播放并有明确 UI 提示。  
3. **G3 可运维性**：提供 **`/health`**、结构化日志、Docker **healthcheck** 支撑部署与排障。  
4. **G4 安全边界**：媒体访问、删除、打开目录等操作 **限制在当前扫描根** 之下。  
5. **G5 可选 AI**：在 **本机 Ollama** 可用时，完成分析 → 人工确认 → 批量重命名闭环。

### 2.2 非目标（Non-Goals）

- **多用户账号体系 / RBAC**（当前为单用户本地工具心智）。  
- **云端同步、在线协作编辑**（数据默认不出本机；Ollama 亦为本地）。  
- **移动端原生 App**（响应式 Web 未在 PRD 中强制验收）。  
- **删除进系统废纸篓**（README backlog 列为未来可能项，**当前实现为硬删**）。

## 3. 用户画像与核心场景

### 3.1 画像

| 代号 | 描述 | 主要诉求 |
|------|------|-----------|
| **P-A** | 家庭用户，外置硬盘存旅行视频/照片 | 快速浏览、全屏播放、偶尔删除废片 |
| **P-B** | 创作者 / 归档人员 | 按文件夹审阅「保留/待审」、键盘高效操作 |
| **P-C** | NAS / Docker 自托管用户 | 局域网访问、健康检查、日志可采集 |
| **P-D** | 希望 AI 辅助命名的人 | 本机 Ollama 分析、表格核对、批量改名 |

### 3.2 核心用户故事（示例）

- **US-1**：作为 P-A，我希望启动后打开浏览器即可看到库中作品卡片，以便无需打开 Finder 层层点目录。  
- **US-2**：作为 P-B，我希望在画廊中用快捷键快进/逐帧/切文件，以便快速判断素材去留。  
- **US-3**：作为 P-C，我希望 `GET /health` 返回磁盘与 ffmpeg 状态，以便监控系统判断实例是否健康。  
- **US-4**：作为 P-D，我希望对一批视频跑 AI 分析并在表格中改标签后批量重命名，以便整理成片文件夹。

## 4. 功能需求（Functional Requirements）

> 编号 **FR-xx** 便于评审与测试用例映射；描述与 **当前实现** 对齐。

### 4.1 扫描与「作品」模型

| ID | 需求描述 | 验收要点 |
|----|-----------|-----------|
| **FR-01** | 扫描根目录可由环境变量 **`MB_ROOT_DIR`** 指定；运行时可通过页眉输入 + **「应用并扫描」** 或 **`POST /api/set-scan-root`** 切换 | 切换后 `scan_root` 与列表刷新；失败返回可读 `error`（v1.2.4：macOS 支持 `/Volumes/…` NAS 挂载路径，拒绝 `smb://` 并提示） |
| **FR-02** | **一级子文件夹**：若其下任意深度存在支持扩展名的视频/图片，则作为一个「作品」 | 与 README「作品规则」一致 |
| **FR-03** | **根目录平铺**：媒体直接位于扫描根且无子目录作品时，合并为虚拟作品「根目录内的媒体…」 | 枚举逻辑与 UI 名称一致 |
| **FR-04** | 枚举跳过 **`.Trash` / `.Trashes`**；安全跟随扫描根内符号链接 | 不索引废纸篓名；越界链接与目录循环被跳过 |
| **FR-05** | 一级枚举无结果时 **整树兜底** 分组 | 深层媒体仍可归纳为作品 |
| **FR-06** | 支持扩展名集合以代码常量为准（含 **`.mts`** 等） | 非法扩展名不出现于列表 |

### 4.2 列表与审阅

| ID | 需求描述 | 验收要点 |
|----|-----------|-----------|
| **FR-10** | 列表支持 **搜索、排序、筛选**（全部 / 有视频 / 有图片 / 仅待审） | 筛选与搜索组合结果正确 |
| **FR-11** | **懒加载**滚动追加卡片 | 大库不一次性渲染全部 DOM |
| **FR-12** | **待审/保留**状态存 **localStorage**（`mb_review_tags` 等）；打开画廊可记「保留」 | 刷新页面后状态保持（同源同浏览器） |
| **FR-13** | 支持批量勾选 → 批量保留/待审；**在文件管理器中打开**作品目录（跨平台） | macOS/Windows/Linux 行为符合 `README` |

### 4.3 画廊与播放

| ID | 需求描述 | 验收要点 |
|----|-----------|-----------|
| **FR-20** | 画廊内播放视频、查看图片；侧栏文件列表与（视频）帧条带 | 与当前 UI 行为一致 |
| **FR-21** | 视频：全屏、静音、音量、逐帧、快捷键快进/快退等 | 与 README「画廊快捷键」表一致 |
| **FR-22** | 图片：滚轮缩放、拖拽平移、双击还原 | 与 README 一致 |
| **FR-23** | 难播格式走 **`/play`** 转码，并有转码中提示 | 非 MP4 友好封装可播放 |
| **FR-24** | 展示视频技术元数据（分辨率、编码、码率、帧率等） | 与 `ffprobe` 解析字段一致 |
| **FR-25** | **删除当前文件**：`POST /delete` + 画廊 **⌘I/Ctrl+I**；删除成功后清理对应缩略图缓存目录 | 路径须在扫描根下 |
| **FR-26** | 列表 **⌘←/⌘→**（或 Ctrl）在画廊关闭时滚动到上/下一作品卡片；画廊内 **⌘←/⌘→** 切换作品并打开首/末媒体 | 与 README 双场景说明一致 |
| **FR-27** | 在作品内翻到最后/首个文件后继续翻页，进入 **下一/上一作品** 的首/末文件 | 跨作品导航 |

### 4.4 AI 视频分析与重命名

| ID | 需求描述 | 验收要点 |
|----|-----------|-----------|
| **FR-30** | 通过 **`/api/tasks`** 系列接口创建任务、触发分析、确认、预览、执行、回滚 | 任务状态机与 UI 可操作 |
| **FR-31** | 分析依赖本机 **Ollama**（`MB_OLLAMA_HOST`、`MB_OLLAMA_MODEL` 等） | 不可用时界面有明确失败信息 |
| **FR-32** | 分析结果含时间/地点/事件/标签/短语；表格中可编辑并由标签生成参考短句 | 与当前「由标签连成句」等 UI 一致 |
| **FR-33** | 重命名 **仅同目录**、预览映射、可回滚 | 不跨目录移动 |

### 4.5 系统、运维与生命周期

| ID | 需求描述 | 验收要点 |
|----|-----------|-----------|
| **FR-40** | **`GET /health`** 返回 JSON：`disk`、`scan`、`ffmpeg`、`ffprobe`、`ollama`、`cache`、`uptime_seconds` 等 | 字段存在且类型合理 |
| **FR-41** | 健康检查在 **关键异常** 时返回 **HTTP 503**（如 ffmpeg 不可用、枚举错误、磁盘将满阈值等） | 与实现及 `docs/TROUBLESHOOTING.md` 一致 |
| **FR-42** | 日志使用 **`logging`**，支持 **`MB_LOG_LEVEL`**、**`MB_LOG_FORMAT`**（`text`/`json`） | 容器与本地均可读 stderr |
| **FR-43** | 页眉 **退出应用** → **`POST /api/shutdown`** 结束进程 | 进程退出、端口释放 |

## 6. 数据与状态

| 数据 | 存储位置 | 说明 |
|------|-----------|------|
| 审阅标签、搜索/排序/筛选偏好 | **浏览器 localStorage** | 不随服务端删除自动清理跨作品逻辑见 README |
| 缩略图缓存 | **`MB_CACHE_DIR`** 下按 `sha256(绝对路径)` 分目录 | 删除源文件时同步删缓存目录 |
| AI 任务与映射 | 服务端内存（当前实现） | 重启丢失；PRD 标注为「会话级」能力 |

## 7. API 与集成（摘要）

完整表见 **[README.md § HTTP 接口](../README.md#http-接口)**。PRD 级摘要：

- **页面**：`GET /`  
- **运维**：`GET /health`  
- **扫描**：`GET /api/progress`、`POST /api/set-scan-root`  
- **媒体**：`GET /file`、`GET /play`、`GET /thumb/...`、`GET /api/preview-thumb`  
- **系统**：`GET /open`、`POST /delete`、`POST /api/shutdown`  
- **AI 任务**：`POST/GET /api/tasks` 及子路径 `analyze` / `confirm` / `preview` / `execute` / `rollback` / `evaluation`

## 9. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 删除仍为永久删除 | 误删数据 | 单文件与整作品删除均要求确认；后续可支持系统废纸篓 |
| 转码高 CPU | 宿主机卡顿 | 用户教育 + 限制同时播放/分析 |
| 容器内访问宿主机 Ollama | AI 不可用 | `TROUBLESHOOTING` 网络说明 |
| 单文件过大 | 协作冲突、review 成本高 | 见 `docs/ARCHITECTURE_REVIEW.md` 拆分建议 |
